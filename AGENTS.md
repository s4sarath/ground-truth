# Ground Truth Blog Rules

Apply these rules to every post and revision. `CLAUDE.md` contains the full version; these are the same mandatory standards in brief.

## Editorial rules

- Write a flowing, source-backed technical story: problem → mental model → evidence → practical consequence.
- Use clear, claim-led headings. Never use `Part N` labels or report-like section names.
- Keep paragraphs concise, professional, and natural. Define terms before using them; remove filler and unsupported claims.
- Distinguish fact, measurement, and inference. State methodology and non-comparable conditions near the relevant result.
- Use tables for multi-dimensional comparisons and a `## References` section with direct authoritative links.

## Required emphasis

- Bold **important measurements, counts, costs, durations, paths, limits, and outcomes** so a skimming reader catches the evidence immediately.
- Bold a crucial conclusion when needed, but never whole paragraphs, consecutive sentences, or routine details. Bold is a scan layer, not decoration.
- In tables, bold the values and outcomes that carry the finding.

## Visual rules

- Keep the existing light-by-default, reader-toggleable dark theme and the restrained editorial design system.
- Preserve compact, readable typography and balanced whitespace. Do not create oversized headings, excessive bold type, accidental blank areas, or card-heavy layouts.
- Use the established creamy neutral canvas, restrained palette, and light violet boundaries.
- Every diagram, chart, trace panel, and explanatory box needs a specific title or caption, meaningful alt text, and a visible light violet boundary. Tables need clear separators.
- Use visuals only to clarify a mechanism, sequence, or comparison. Ensure responsive layouts have no overflow, overlaps, tiny labels, or excessive image height.
- Respect semantic headings, contrast, keyboard focus, and accessible controls.

## Delivery

- Keep post assets with the post, verify internal links and Markdown rendering, and run `mkdocs build --strict` before completion.
